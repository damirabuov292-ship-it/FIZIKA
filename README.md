# JUZ40 PHYSICS | Дамир ағай

ҰБТ-ға дайындыққа арналған интерактивті физика платформасы: теория, A/B/C деңгейлі есептер (толық шешімімен), жеке «Симуляторлар» зертханасы, 6 ойын, рейтинг, оқушы профилі және AI арқылы материал жүктейтін әкімші панелі.

Стек: Next.js 14 (App Router) · TypeScript · Tailwind CSS · Supabase (Auth, PostgreSQL, Storage) · Claude API · KaTeX · Recharts · Vercel.

---

## 1. Құрылымы

| Бөлім | Маршрут | Ескерту |
|---|---|---|
| Басты бет | `/` | Прогресс, тірі симуляция, ұсынылатын жаттығулар |
| Теория | `/theory` | KaTeX формулалары, симуляторға және есептерге сілтеме |
| Есептер | `/problems` | Тақырып / деңгей / түр бойынша сүзгі, серверде тексерілетін жауап |
| Симуляторлар | `/simulators`, `/simulators/[slug]` | Жеке зертхана, басқа бөлімдерге тәуелсіз |
| Ойындар | `/games`, `/games/[id]` | Формула батл, сәйкестендіру, 60 с викторина, толықтыру, ақиқат/жалған, челлендж |
| Рейтинг | `/rating` | Жалпы, апталық, айлық, тақырыптық |
| Менің профилім | `/profile` | Статистика, жетістіктер, «Қателермен жұмыс» |
| Админ панелі | `/admin/*` | Тек әкімшіге (рөл серверде тексеріледі) |

Маңызды файлдар:

- `supabase/migrations/0001_init.sql` — кестелер, RLS, XP мен жауапты тексеретін SQL функциялары, Storage бакеті
- `supabase/seed.sql` — бастапқы контент (JUZ40 «Физика. 2-ай 2-апта»: §1–§9, 32 сұрақ, 50 ойын элементі, 8 симулятор)
- `supabase/admin_setup.sql` — әкімшіні тағайындау
- `src/lib/pipeline.ts` — файлды өңдеу: мәтін алу → AI → тексеру → жоба
- `src/lib/verify.ts` — сандық жауапты mathjs арқылы детерминистік тексеру
- `src/lib/sims/library.js` — симуляторлар кітапханасы (физикалық модельдер)

## 2. Supabase-ті баптау

1. [supabase.com](https://supabase.com) сайтында жаңа жоба ашыңыз (аймақ: Frankfurt немесе жақын).
2. **SQL Editor** → `supabase/migrations/0001_init.sql` мазмұнын қойып, **Run**.
3. Сол жерде `supabase/seed.sql` мазмұнын қойып, **Run** (бастапқы контент).
4. **Authentication → URL Configuration**:
   - Site URL: `https://<сіздің-домен>.vercel.app`
   - Redirect URLs: `https://<сіздің-домен>.vercel.app/auth/callback` және жергілікті тест үшін `http://localhost:3000/auth/callback`
5. **Authentication → Providers → Email**: қосулы, «Confirm email» қосулы болсын. Құпиясөздің ең аз ұзындығын 8 етіп қойыңыз.
6. **Project Settings → API** бетінен `Project URL`, `anon` және `service_role` кілттерін алыңыз.

## 3. Ортаның айнымалылары

`.env.example` файлын `.env.local` деп көшіріп, толтырыңыз:

| Айнымалы | Қайдан | Қайда қолданылады |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → API | Браузер және сервер |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase → API (anon) | Браузер және сервер (RLS қорғайды) |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → API (service_role) | **Тек сервер.** Файл өңдеу, оқушылар тізімі, бұғаттау |
| `ANTHROPIC_API_KEY` | console.anthropic.com | **Тек сервер.** Материал өңдеу, сұрақ генерациясы |
| `ANTHROPIC_MODEL` | — | Әдепкі: `claude-sonnet-5-5` |
| `NEXT_PUBLIC_SITE_URL` | Vercel домені | Email сілтемелері |

Құпия кілттер ешқашан `NEXT_PUBLIC_` префиксімен жазылмайды және браузерге жіберілмейді.

```bash

```

## 5. Vercel-ге орналастыру

1. Жобаны GitHub-қа жүктеңіз.
2. [vercel.com](https://vercel.com) → **Add New → Project** → репозиторийді таңдаңыз (Framework: Next.js, анықталады).
3. **Environment Variables** бөліміне 3-кестедегі барлық айнымалыны қосыңыз.
4. **Deploy**. Аяқталған соң доменді Supabase-тегі Site URL және Redirect URLs-ке жазыңыз (2-қадам, 4-тармақ).
5. Үлкен файлдарды өңдеу 1–3 минут алуы мүмкін. Өңдеу маршрутында `maxDuration = 300` қойылған: бұл Vercel Pro жоспарында жұмыс істейді. Hobby жоспарында функция уақыты шектеулі, сондықтан үлкен PDF-тер үзілуі мүмкін (ондайда файлды бөліп жүктеңіз немесе Pro-ға өтіңіз).

## 6. Әкімшіні тағайындау (бір рет)

1. Сайтта өз email-іңізбен тіркеліп, растаңыз.
2. Supabase **SQL Editor**-де: `select public.set_admin('сіздің@email.kz');`
3. Сайтқа қайта кіріңіз — навигацияда «Админ панелі» пайда болады.

Әкімші рөлін тек осы SQL функциясы береді. Оқушы өз рөлін, XP-ын немесе есептегіштерін өзгерте алмайды (бағандық құқықтар + RLS), ал дерекқорда әкімші тек біреу болуы мүмкін (бірегей индекс).

## 7. Жаңа материал қосу (код жазбай)

1. **Админ панелі → Файл жүктеу**: PDF, DOCX, PPTX, TXT, XLSX немесе сурет (бірнеше файл, әрқайсысы 50 МБ-қа дейін).
2. Файл жабық бакетке жүктеледі → AI өңдейді: тақырыптар, теория, 4 түрлі сұрақ, шешімдер, ойын элементтері, симулятор ұсыныстары. PDF пен суреттер AI-ға тікелей беріледі (сканерленген беттер мен формулаларды оқиды). Сенімсіз оқылған жерлер «Қолмен тексеруді қажет етеді» тізіміне шығады.
3. Әр сұрақ автоматты тексеріледі: сандық жауап `answer_expr` өрнегінен mathjs арқылы қайта есептеледі, дұрыс нұсқамен, бірлікпен, басқа нұсқалармен салыстырылады. Өтпегендері «Тексеруден өтпеді» күйінде қалады.
4. **Сұрақтарды тексеру**: өңдеңіз, «Сақтау және тексеру», содан кейін «Жариялау». Тексерілмеген сұрақты жариялау дерекқор деңгейінде тыйым салынған.
5. Теория бөлімдері мен ойын элементтері де жоба күйінде түседі — оларды да қарап, жариялаңыз.

Жұмыс ағыны: **Uploaded → Processing → Draft → Verification → Admin Review → Published**

## 8. Симуляторлар

- Кітапханада 8 модуль бар: түзусызықты қозғалыс, лақтырылған дене, Ньютонның II заңы, көлбеу жазықтық, шеңбер бойымен қозғалыс, импульс және соқтығысулар, электр тізбегі, жұқа линза.
- **Админ панелі → Симуляторлар**: кітапханадағы модульден жаңа симулятор жасау, атауы, сипаттамасы, санаты, әдепкі мәндер мен ауқымдар, тақырыптарға байланыстыру, жариялау/жасыру — кодсыз.
- Физикалық моделі мүлде жаңа симулятор (мысалы, газ заңдары) үшін `src/lib/sims/library.js` файлына жаңа модуль жазылады, тексеріледі, содан кейін әкімші оны жариялайды. Жүктелген кез келген құжаттан дәл симулятор автоматты түрде жасалмайды.

## 9. Қауіпсіздік

- Әкімші құқығы серверде тексеріледі (`requireAdminPage`, `adminOrNull`) және RLS арқылы қайталанады.
- Оқушылар `questions` кестесін тікелей оқи алмайды: дұрыс жауапсыз `questions_public` және `game_items_public` көріністері ғана ашық.
- Жауап пен XP тек `record_answer` / `record_game_answer` SQL функцияларында есептеледі; бір сұрақ үшін XP бір рет беріледі (`xp_events` бірегей кілті).
- Жиілік шектеулері: жауаптар (40/мин), ойындар (60/мин), әкімші API (120/мин), AI өңдеу (10/10 мин).
- Файлдар жабық `materials` бакетінде, тек әкімші қол қойылған URL арқылы жүктейді; түрі мен өлшемі тексеріледі.
- Барлық кіріс деректер zod арқылы тексеріледі. Құпиясөздерді Supabase Auth хэштейді.

## 10. Тестілеу жағдайы

Осы жобаны жасау ортасында npm реестрі қолжетімсіз болды, сондықтан `npm install`, `next build` және браузерлік тесттер **әлі іске қосылмаған**. Тексерілгендері:

- ✅ SQL миграциясы мен seed PostgreSQL 16-да (Supabase auth/storage үлгісімен) қатесіз орындалды.
- ✅ RLS және XP тұтастығы: оқушы `xp`/`role`-ді өзгерте алмайды, `xp_events`-ке жаза алмайды, жауаптарды көрмейді; қайта дұрыс жауап XP бермейді; тексерілмеген сұрақ жарияланбайды; әкімші біреу ғана.
- ✅ Бастапқы 20 сандық есептің жауабы екі тәуелсіз жолмен есептеліп, сәйкестігі тексерілді.
- ✅ `verify.ts` тексерушісі: дұрыс/қате белгі, AI-дың қате жауабы, екі дұрыс нұсқа, бірлік, бұрыш жағдайлары.
- ✅ Симулятор модельдері қолмен есептелген мәндермен салыстырылды (лақтыру: h = 10,2 м, L = 40,8 м; серпімді соқтығысу: импульс пен энергия сақталады; линза: d = 30, F = 12 → f = 20 см).
- ✅ Барлық TypeScript файлдары синтаксис бойынша тексерілді.

Іске қоспас бұрын орындаңыз: `npm install && npm run typecheck && npm run build`, содан кейін 13-бөлімдегі (QA) тізім бойынша тіркелу, жауап беру, файл жүктеу (әр түрі), рейтинг пен мобильді көріністі тексеріңіз.
